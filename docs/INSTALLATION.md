# Установка и восстановление

## Первый запуск

```sh
curl -fsSL https://raw.githubusercontent.com/Lfyz-git/Stolas/v0.5.0/bootstrap.sh | sh
```

По умолчанию мастер предложит `~/stolas`, доступный обычному пользователю. Запускайте от пользователя с доступом к локальному Docker и каталогу установки.
Если каталога ещё нет, администратор может создать его:

```sh
sudo install -d -o "$USER" -g "$(id -gn)" /opt/stolas
```

Загрузчик проверяет SHA-256 архива релиза. Это проверка целостности, а не
отдельная подпись издателя. Можно сначала скачать и изучить bootstrap.
`--ref v0.5.0` фиксирует версию; для ветки или полного SHA требуется также
`--sha256` доверенного архива. Без `--dir` мастер спросит каталог.

`--configure-only` сохраняет настройки без Docker и теста.
Установка Python до мастера требует согласия. До итогового подтверждения
мастер не меняет Docker, firewall, маршруты и сервисы.

## Рабочие файлы

```text
/opt/stolas/
├── compose.yaml
├── .env
├── stolas
├── config/local.json
└── .stolas/
    ├── installer/
    ├── build/
    ├── state/
    ├── backups/
    └── integrations/
```

`.stolas/build` — локальный контекст Docker с закреплёнными зависимостями.
`.stolas/state` — журнал, идентификатор экземпляра, черновик и сведения о ресурсах.
`.stolas/backups/transactions` — снимки предыдущих версий;
`.stolas/backups/settings` — копии изменённых настроек.
SQLite хранится в Docker volume, точное имя записано в `.env` и состоянии.

Приватные файлы имеют режим 600, служебные каталоги — 700.
`config/local.json` доступен для чтения nonroot-процессу контейнера и не должен
содержать секреты; API-токен находится в `.env`. Не публикуйте `.stolas` и `.env`.

## Обновить с v0.4.0

```sh
curl -fsSL https://raw.githubusercontent.com/Lfyz-git/Stolas/v0.5.0/bootstrap.sh | sh -s -- --dir /opt/stolas --action update
```

Каталог и Docker-ресурсы мигрируют одной транзакцией. Старое имя с хешем
заменяется на `stolas`; при конфликте выбирается пользовательское имя.
Существующий пользовательский project сохраняется.
Имя контейнера совпадает с именем проекта, образ имеет тег версии.

Фактически подключённый volume истории сохраняется под прежним именем и
подключается как external volume. Новое имя проекта не создаёт пустую историю.
Токен, адрес и порт API, параметры измерений остаются прежними.
Кандидат собирается и проверяется до остановки старого контейнера; затем
запускается один новый экземпляр. Ошибка возвращает прежние файлы и сервис.
Нагрузочного теста при update нет.

Старые управляемые файлы и резервные копии переносятся в снимок транзакции.
Тесты, CI и исходники разработчика удаляются из видимого корня после успеха.
Неизвестные пользовательские файлы сохраняются.

## Обновить и откатить

В новой установке из её каталога:

```sh
./stolas update
./stolas update --version v0.5.0
./stolas rollback
```

Update требует GitHub; rollback использует локальную резервную копию.
Откат восстанавливает настройки из снимка, сохраняя текущий SQLite volume.
После отката на v0.4.0 возвращается её структура и `install.sh`;
для следующего обновления снова используйте bootstrap v0.5.0.
Не удаляйте `.stolas/backups` до проверки новой версии.

## После прерывания

Повторите исходную команду. Для прерванного обновления сначала восстанавливается
предыдущая установленная версия, затем начинается новая попытка.
Для незавершённой чистой установки предлагается продолжить черновик.
`:cancel` отменяет мастер, Ctrl+C сохраняет завершённые шаги.
Первичный тест с сохранённой отметкой о завершении не повторяется при продолжении.

Код 0 — завершено; 1 — ошибка; 2 — агент установлен, результат измерения
требует внимания; 3 — отмена; 130 — прерывание.
Смешанные IP при успешном замере дают предупреждение, но не код ошибки установки.

## Диагностика

```sh
./stolas diagnose
./stolas diagnose --json
```

Диагностика не меняет пакеты, контейнеры или конфигурацию; JSON не содержит секретов.
Без установленной команды используйте bootstrap с `--diagnose --dir /opt/stolas`.

## Удалить

```sh
./stolas uninstall
```

Выберите сохранение истории, полное удаление или отмену.
Первый вариант сохраняет volume, настройки, резервные копии и команду управления;
восстановить агент можно через `./stolas update`.

```sh
./stolas uninstall --purge
```

Полное удаление показывает точные каталог и volume и требует слова `УДАЛИТЬ`.
Удаляются только контейнеры этого каталога, образы с записанными ID, собственный
volume и перечисленные управляемые файлы. Чужие файлы остаются на месте.
Образ, используемый другим контейнером, сохраняется. Volume, подключённый к
другому контейнеру, не удаляется; команда объяснит, что нужно отключить.
Повторный запуск после частичного удаления продолжает очистку.

Удаление не обращается к GitHub или n8n. Для старой v0.4.0 без команды `stolas`
можно заранее скачать bootstrap v0.5.0 и архив релиза или использовать его
`--action uninstall`: загрузка нужна только для получения нового инструмента,
само удаление выполняется локально без предварительной миграции Core.
При сохранении истории инструмент оставляет `./stolas`, чтобы повторное
удаление и purge работали без загрузки. Старые исходники программы удаляются;
история, настройки и резервные копии остаются.
