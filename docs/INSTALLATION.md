# Установка и восстановление

## Первый запуск

```sh
curl -fsSL https://raw.githubusercontent.com/Lfyz-git/Stolas/v0.5.1/bootstrap.sh | sh
```

По умолчанию мастер предложит `~/stolas`, доступный обычному пользователю. Запускайте от пользователя с доступом к локальному Docker и каталогу установки.
Если каталога ещё нет, администратор может создать его:

```sh
sudo install -d -o "$USER" -g "$(id -gn)" /opt/stolas
```

Загрузчик проверяет SHA-256 архива релиза. Это проверка целостности, а не
отдельная подпись издателя. Можно сначала скачать и изучить bootstrap.
`--ref v0.5.1` фиксирует версию; для ветки или полного SHA требуется также
`--sha256` доверенного архива. Без `--dir` мастер спросит каталог.

`--configure-only` сохраняет настройки без Docker и теста.
Установка Python до мастера требует согласия. До итогового подтверждения
мастер не меняет Docker, firewall, маршруты и сервисы.

Путь установки Docker проверяется автоматическим тестом чистой runtime-структуры
без Docker CLI; apt в нём симулирован. Полная установка пакетов на чистом
Ubuntu/Debian-хосте пока отдельно не проверена.

## Команда из любого каталога

После успешной установки и первого теста мастер предложит добавить команду
в PATH. Пользовательский вариант — `~/.local/bin/stolas`, без sudo.
Если этот каталог уже в PATH, он выбран по умолчанию; иначе по умолчанию
выбрано «Позже», а после выбора установки будет показана строка `export PATH=…`.
Для постоянного PATH внесите её в настройки оболочки вручную.

```sh
cd /opt/stolas
./stolas command install
# Или явно выбрать пользовательский каталог и имя второго экземпляра:
./stolas command install --scope user --name stolas-home
cd /tmp
stolas history
stolas configure
stolas run
```

Для `/usr/local/bin` выберите общесистемный вариант либо `--scope system`:
нужны права записи и отдельное подтверждение. Установщик не вызывает sudo
для создания команды. Существующие файлы, symlinks и чужие команды в PATH
не перезаписываются. При конфликте укажите другое имя; основной экземпляр
автоматически не переключается.

Обёртка запускает абсолютный путь именно этой установки, сохраняет аргументы,
код завершения и сигналы. В неё не копируются `.env` или токены. Рабочий каталог
вызывающей оболочки не меняется; внутренние команды используют каталог установки.
Операции управления доступны через неё, включая update, rollback и uninstall.
`./stolas` остаётся локальным способом запуска без PATH.

```sh
./stolas command status
./stolas command remove
```

При sudo значения HOME и PATH могут отличаться: пользовательская команда
может быть недоступна, а `--scope user` будет относиться к HOME этой сессии.
Состояние команды сохраняет владельца служебного каталога установки.
Удаление общесистемной команды также требует прав записи в `/usr/local/bin`;
если их нет, uninstall остановится до удаления Docker-ресурсов с инструкцией.
Если нужны повышенные права для Docker, используйте абсолютный путь:
`sudo /opt/stolas/stolas history`. Членство в группе `docker` предоставляет
полномочия root; после ручного изменения групп нужен новый вход в сессию.
Установщик проверяет прямой доступ, предупреждает о его отсутствии даже при
успешном `sudo -n docker info` и не меняет группы или права Docker socket.

## Рабочие файлы

```text
/opt/stolas/
├── compose.yaml
├── .env
├── stolas
├── config/local.json
└── .stolas/
    ├── installer/
    ├── build/
    ├── state/
    ├── backups/
    └── integrations/
```

`.stolas/build` — локальный контекст Docker с закреплёнными зависимостями.
`.stolas/state` — журнал, идентификатор экземпляра, черновик и сведения о ресурсах.
`.stolas/backups/transactions` — снимки предыдущих версий;
`.stolas/backups/settings` — копии изменённых настроек.
SQLite хранится в Docker volume, точное имя записано в `.env` и состоянии.

Приватные файлы имеют режим 600, служебные каталоги — 700.
`config/local.json` доступен для чтения nonroot-процессу контейнера и не должен
содержать секреты; API-токен находится в `.env`. Не публикуйте `.stolas` и `.env`.

## Обновить с v0.4.0

```sh
curl -fsSL https://raw.githubusercontent.com/Lfyz-git/Stolas/v0.5.1/bootstrap.sh | sh -s -- --dir /opt/stolas --action update
```

Каталог и Docker-ресурсы мигрируют одной транзакцией. Старое имя с хешем
заменяется на `stolas`; при конфликте выбирается пользовательское имя.
Существующий пользовательский project сохраняется.
Имя контейнера совпадает с именем проекта, образ имеет тег версии.

Фактически подключённый volume истории сохраняется под прежним именем и
подключается как external volume. Новое имя проекта не создаёт пустую историю.
Токен, адрес и порт API, параметры измерений остаются прежними.
Кандидат собирается и проверяется до остановки старого контейнера; затем
запускается один новый экземпляр. Ошибка возвращает прежние файлы и сервис.
Нагрузочного теста при update нет.

Старые управляемые файлы и резервные копии переносятся в снимок транзакции.
Тесты, CI и исходники разработчика удаляются из видимого корня после успеха.
Неизвестные пользовательские файлы сохраняются.

## Обновить и откатить

В новой установке из её каталога:

```sh
./stolas update
./stolas update --version v0.5.1
./stolas rollback
```

Update требует GitHub; rollback использует локальную резервную копию.
Откат восстанавливает настройки из снимка, сохраняя текущий SQLite volume.
После отката на v0.4.0 возвращается её структура и `install.sh`;
для следующего обновления снова используйте bootstrap v0.5.1.
Если настроена команда в PATH, откат сохраняет текущие launcher и инструмент
управления вместе с ownership команды. Core, Compose и настройки возвращаются
из снимка; версия образа определяется по восстановленному Compose. Это позволяет
использовать и удалить команду даже после отката на версию до поддержки PATH.
Не удаляйте `.stolas/backups` до проверки новой версии.

## После прерывания

Повторите исходную команду. Для прерванного обновления сначала восстанавливается
предыдущая установленная версия, затем начинается новая попытка.
Для незавершённой чистой установки предлагается продолжить черновик.
`:cancel` отменяет мастер, Ctrl+C сохраняет завершённые шаги.
Первичный тест с сохранённой отметкой о завершении не повторяется при продолжении.

Код 0 — завершено; 1 — ошибка; 2 — агент установлен, результат измерения
требует внимания; 3 — отмена; 130 — прерывание.
Смешанные IP при успешном замере дают предупреждение, но не код ошибки установки.

## Диагностика

При update через sudo владельцем управляемых файлов, состояния и новых резервных
копий остаётся владелец каталога установки. Установка, изначально принадлежащая
root, остаётся системной и требует повышенных прав управления. Режимы приватных
файлов — 0600, служебных каталогов — 0700; ослабления прав нет.

Перед изменениями проверяются права доступа. `diagnose` показывает безопасные
метаданные uid/gid/mode и возможность чтения/записи управляемых путей, без чтения
токенов в вывод. Ошибки указывают конкретный путь и причину, а подсказка использует
настроенную команду в PATH или абсолютный путь к launcher.

Если старая sudo-установка уже оставила root-owned файлы внутри пользовательского
каталога, сначала проверьте вывод diagnose через bootstrap или с sudo. Новая запись
управляемых файлов от root сохраняет владельца установки; ранее не затронутые
резервные копии могут потребовать адресного восстановления владельца администратором.
Не выполняйте рекурсивный chown всего каталога: посторонние файлы могут иметь другого
владельца намеренно. Hardlinks и symlinks в управляемых путях не используются для
смены владельца.

```sh
./stolas diagnose
./stolas diagnose --json
```

Диагностика не меняет пакеты, контейнеры или конфигурацию; JSON не содержит секретов.
Без установленной команды используйте bootstrap с `--diagnose --dir /opt/stolas`.

## Удалить

```sh
./stolas uninstall
```

Выберите сохранение истории, полное удаление или отмену.
Первый вариант сохраняет volume, настройки, резервные копии и команду управления;
восстановить агент можно через `./stolas update`.
Оба режима удаления убирают только собственную неизменённую обёртку из PATH.
Изменённая пользователем команда сохраняется с предупреждением. Локальный
`./stolas` при обычном удалении остаётся для восстановления и повторного purge.

```sh
./stolas uninstall --purge
```

Полное удаление показывает точные каталог и volume и требует слова `УДАЛИТЬ`.
Удаляются только контейнеры этого каталога, образы с записанными ID, собственный
volume и перечисленные управляемые файлы. Чужие файлы остаются на месте.
Образ, используемый другим контейнером, сохраняется. Volume, подключённый к
другому контейнеру, не удаляется; команда объяснит, что нужно отключить.
Повторный запуск после частичного удаления продолжает очистку.

Удаление не обращается к GitHub или n8n. Для старой v0.4.0 без команды `stolas`
можно заранее скачать bootstrap v0.5.1 и архив релиза или использовать его
`--action uninstall`: загрузка нужна только для получения нового инструмента,
само удаление выполняется локально без предварительной миграции Core.
При сохранении истории инструмент оставляет `./stolas`, чтобы повторное
удаление и purge работали без загрузки. Старые исходники программы удаляются;
история, настройки и резервные копии остаются.
