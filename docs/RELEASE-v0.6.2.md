# Stolas v0.6.2

Исправлены issue #3, #4 и #5: накладные расходы измерений, накопление копий
транзакций и привязка мастера n8n к сетевой технологии.

DNS и WAN guard используют один изолированный процесс на цикл. Каждая проверка
заново получает маршрут и внешний IP: проверки до и после download/upload
сохранены. Независимое подтверждение низкой скорости, резервная периодичность,
длительность передач и пороги не изменены. Если после таймаута остаётся зависший
поток, процесс завершается; следующая проверка запускает новый. Общие сроки
включают запуск процесса; прямой HTTPS без прокси, запрет редиректов и проверки
ответов сохранены.

Результат JSON содержит числовой объект `timings`: DNS, запуск процесса,
WAN-проверки, локальный маршрут, HTTPS, задержки повторов, iperf и остальные
накладные расходы. Времена маршрута/HTTPS входят в WAN, а запуск процесса входит
в первый DNS/WAN вызов: эти поля нельзя складывать как независимые интервалы.
`iperf_seconds` включает неудачные попытки. Новые поля не содержат адресов и имён.

На локальном стенде с двумя независимыми loopback-серверами, четырьмя передачами
по одной секунде и восемью HTTPS-проверками искусственная задержка запуска Python
3,6 с дала 41,079 с до изменения и 7,936 с после. Число запусков снизилось с десяти
до одного; iperf занял 4,025 и 4,034 с соответственно. Это воспроизводит цену
инициализации, а не прогноз производительности рабочего канала.

После успешного обновления или изменения настроек сохраняются три завершённые
копии в `.stolas/backups/transactions`. Самые старые удаляются по сохранённому
порядку создания; перевод часов назад его не меняет. Копия, указанная в журнале
отката, защищена и занимает один из трёх слотов. Незавершённые/прерванные копии
сохраняются дополнительно. Копии старых релизов без признака завершения не
удаляются наугад: последняя подтверждённая журналом копия мигрирует автоматически,
остальные неоднозначные копии сохраняются с предупреждением для ручного аудита.

Очистка выполняется только после фиксации транзакции. Ссылки, повреждённые снимки,
посторонние каталоги и ошибки удаления приводят к сохранению данных и предупреждению.
Настройки, SQLite, Docker-тома и другие каталоги резервных копий не очищаются.

Мастер n8n предлагает три размещения: Docker на хосте Stolas, приложение на том же
хосте и другой хост. Локальный listener и URL клиента независимы. Для другого
хоста доступны обнаруженные IPv4 и ручной IPv4:порт; LAN и overlay-сети не
разделяются. HTTP требует подтверждения доверия, широкая привязка — отдельного
разрешения. HTTPS endpoint можно задать с loopback listener для reverse proxy.
Старые схемы переносятся с подтверждением без скрытой смены listener.
[Подробности подключения n8n](N8N.md).

Штатное обновление:

```sh
stolas update
```

Из каталога установки без команды в PATH: `sh ./stolas update`.
Архив `stolas-v0.6.2.tar.gz` и `SHA256SUMS` предназначены для штатного загрузчика.
