# Настройки

`config/local.json` — параметры измерений; `.env` — параметры HTTP-сервиса.
Меняйте их через `./stolas configure` или вручную, затем:

```sh
docker compose up -d --force-recreate stolas
```

Проверка файла без измерения:

```sh
docker compose run --rm --no-deps stolas validate
```

## Серверы

```json
"server_groups": {
  "primary": {"selection":"sequential","servers":[
    {"id":"primary-1","host":"speed.example.net","ports":[5201,5202],
     "min_download_mbps":500,"min_upload_mbps":500}
  ]},
  "additional": {"selection":"random","servers":[]},
  "emergency": {"selection":"sequential","servers":[]}
}
```

В основной группе нужен хотя бы один сервер; остальные могут быть пустыми.
Количество серверов не ограничено, имена и хосты должны различаться во всех группах.
Сначала используются основные, затем дополнительные, затем аварийные.
`sequential` продолжает очередь между циклами, `random` перебирает случайный порядок
без повторов внутри цикла. За один цикл выбирается один полноценный замер из группы.
Для подтверждения снижения нужен другой фактический IPv4, а не другое DNS-имя того же IP.

Порты: от 1 до 9 на сервер. Занятые порты пропускаются в рамках
`busy_attempts_per_server`; обычные ошибки учитываются в `attempts_per_server`.
`reserve_every` задаёт периодический контроль дополнительных групп.
Старый плоский список `servers` читается с сохранением порядка: первый основной,
второй дополнительный, остальные аварийные. Новая запись использует группы.

## Измерение

Defaults: 10 секунд на направление, 4 потока, TCP IPv4. Пороги задаются для
каждого сервера. `process_timeout` должен покрывать тест и подключение;
`cycle_timeout` ограничивает весь цикл. `retry_delay` задаёт паузу повтора,
`min_interval` — защиту от частого запуска, `history_limit` — число сохранённых циклов.
`bind_address` необязателен и ограничивает исходящий адрес iperf.

## Проверка канала

`route.mode=required` сохраняет проверку перед измерениями. `off` отключает её
явно; при этом `wan_alert` не устанавливается.

`expected_public_cidrs` — известный внешний IPv4/32 или диапазоны основного WAN.
Не подставляйте текущий обнаруженный IP автоматически: он может принадлежать VPN/LTE.
`public_ip_urls` — HTTPS-источники IPv4 без credentials/query;
`source_timeout` и `verification_timeout` ограничивают время опроса.

| Наблюдение | Решение | Статус проверки |
| --- | --- | --- |
| Все успешные ответы совпадают с разрешённым IP и достигнут `min_confirmations` | Измерять | `verified`, `verified=true` |
| Разные IP, хотя бы один разрешён | Предупредить и измерять | `mixed`, `verified=false` |
| Есть ответы, но нет разрешённого IP | Блокировать | `mismatch` |
| Нет ответов либо недостаточно одинаковых подтверждений | Блокировать | `unavailable` |
| Явно заданный интерфейс/шлюз не совпадает с маршрутом к серверу | Блокировать | `mismatch` |

При смешанных ответах правило «хотя бы один разрешённый» применяется независимо
от `min_confirmations`; неоднозначность сохраняется в результате, а не скрывается.
Низкая скорость при `mixed` не создаёт `wan_alert`.

`interface` и `gateway` необязательны и проверяются через `ip route get` для адреса
измерительного сервера. Совпадение LAN-шлюза не подтверждает внешний WAN.
HTTPS-источники и iperf3 имеют разные назначения: маршрутизатор с policy-based
routing может отправлять их через разные VPN/WAN.

`verified` описывает согласованность HTTPS-проверки. `egress_verified=false`
явно показывает, что внешний маршрут самого iperf3 не установлен.
При `mixed` выводится предупреждение о раздельной маршрутизации; ответы всех
источников остаются в `attempts[].route_checks[].sources`, предупреждение — в `warnings`.
Никакая модель конкретного маршрутизатора не требуется.

Если LTE запрещён для нагрузочных тестов, закрепите маршрут к измерительным
серверам за основным WAN на маршрутизаторе. Одних HTTPS-свидетелей за LAN-шлюзом
недостаточно для строгой гарантии. Когда все ответы показывают запрещённый LTE,
Stolas блокирует тест; когда запрещённый маршрут виден только маршрутизатору,
хост не может достоверно обнаружить его этой проверкой.

## Переменные окружения

`STOLAS_API_TOKEN`, `STOLAS_LISTEN`, `STOLAS_PORT` — API; `STOLAS_LOG_LEVEL`,
`STOLAS_LOG_FORMAT` — логи. API-токен содержит не менее 32 случайных ASCII-символов.
Мастер создаёт его самостоятельно. Для Docker `.env` читается Compose.

`STOLAS_PROJECT_NAME` и `STOLAS_CONTAINER_NAME` задают имя экземпляра;
`STOLAS_INSTANCE_ID` и `STOLAS_DATA_VOLUME` фиксируют его принадлежность и историю.
Их заполняет установщик. Не переименовывайте ресурсы вручную: используйте обновление
или отдельную установку. В нормальном случае имена проекта и контейнера — `stolas`.

В автономном CLI параметры конфигурации можно переопределять `STOLAS_<ИМЯ>`;
значения, кроме `STOLAS_NODE`, кодируются JSON. Например `STOLAS_PARALLEL=4`.
`STOLAS_SERVER_GROUPS` и `STOLAS_ROUTE` задают целый объект. Совместимость с
`STOLAS_SERVERS` и старым `public_ip_url` сохранена; одновременно старую и новую
формы не задавайте. Мастер изолирован от этих overrides, чтобы сохранить именно
подтверждённые настройки.
