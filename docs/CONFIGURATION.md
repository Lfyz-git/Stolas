# Настройки

`config/local.json` — параметры измерений; `.env` — параметры HTTP-сервиса.
Меняйте их через `sh install.sh --action reconfigure` или вручную, затем:

```sh
docker compose up -d --force-recreate stolas
```

Проверка файла без измерения:

```sh
docker compose run --rm --no-deps stolas validate
```

## Серверы

```json
"server_groups": {
  "primary": {"selection":"sequential","servers":[
    {"id":"primary-1","host":"speed.example.net","ports":[5201,5202],
     "min_download_mbps":500,"min_upload_mbps":500}
  ]},
  "additional": {"selection":"random","servers":[]},
  "emergency": {"selection":"sequential","servers":[]}
}
```

В основной группе нужен хотя бы один сервер; остальные могут быть пустыми.
Количество серверов не ограничено, имена и хосты должны различаться во всех группах.
Сначала используются основные, затем дополнительные, затем аварийные.
`sequential` продолжает очередь между циклами, `random` перебирает случайный порядок
без повторов внутри цикла. За один цикл выбирается один полноценный замер из группы.
Для подтверждения снижения нужен другой фактический IPv4, а не другое DNS-имя того же IP.

Порты: от 1 до 9 на сервер. Занятые порты пропускаются в рамках
`busy_attempts_per_server`; обычные ошибки учитываются в `attempts_per_server`.
`reserve_every` задаёт периодический контроль дополнительных групп.
Старый плоский список `servers` читается с сохранением порядка: первый основной,
второй дополнительный, остальные аварийные. Новая запись использует группы.

## Измерение

Defaults: 10 секунд на направление, 4 потока, TCP IPv4. Пороги задаются для
каждого сервера. `process_timeout` должен покрывать тест и подключение;
`cycle_timeout` ограничивает весь цикл. `retry_delay` задаёт паузу повтора,
`min_interval` — защиту от частого запуска, `history_limit` — число сохранённых циклов.
`bind_address` необязателен и ограничивает исходящий адрес iperf.

## Проверка канала

`route.mode=required` запрещает тест при несовпадении IP, отсутствии разрешённых
CIDR, конфликтующих ответах или невозможности проверки. `off` отключает проверку
явно; при этом `wan_alert` не устанавливается даже при низкой скорости.

`expected_public_cidrs` — внешний IPv4/32 или доверенные диапазоны основного WAN.
`public_ip_urls` — несколько HTTPS-источников IPv4 без credentials/query;
`source_timeout`, `verification_timeout` и `min_confirmations` ограничивают
проверку и задают число согласных ответов. `interface` и `gateway` необязательны:
если заданы, сверяются с фактическим маршрутом Linux.

## Переменные окружения

`STOLAS_API_TOKEN`, `STOLAS_LISTEN`, `STOLAS_PORT` — API; `STOLAS_LOG_LEVEL`,
`STOLAS_LOG_FORMAT` — логи. API-токен содержит не менее 32 случайных ASCII-символов.
Мастер создаёт его самостоятельно. Для Docker `.env` читается Compose.

В автономном CLI параметры конфигурации можно переопределять `STOLAS_<ИМЯ>`;
значения, кроме `STOLAS_NODE`, кодируются JSON. Например `STOLAS_PARALLEL=4`.
`STOLAS_SERVER_GROUPS` и `STOLAS_ROUTE` задают целый объект. Совместимость с
`STOLAS_SERVERS` и старым `public_ip_url` сохранена; одновременно старую и новую
формы не задавайте. Мастер изолирован от этих overrides, чтобы сохранить именно
подтверждённые настройки.
