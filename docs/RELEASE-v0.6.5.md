# Stolas v0.6.5

Мастер n8n теперь принимает указанные пользователем HTTP/HTTPS адреса в обоих
направлениях подключения. HTTP другого хоста больше не отклоняется из-за того,
что адрес не является localhost. Хост, схема и путь сохраняются; Stolas
не выбирает маршрут и не настраивает DNS, VPN, firewall или TLS-прокси.

Каждый HTTP-адрес требует отдельного подтверждения предупреждения, включая
localhost. По умолчанию выбрана отмена. Отказ происходит до ввода ключа n8n,
применения настроек и запросов к отклонённому endpoint. Подсказки различают
Bearer-токен Stolas и API key n8n.

Встроенный API Stolas работает по HTTP. Для HTTPS нужен заранее настроенный
reverse proxy с сертификатом; выпуск, продление и доверие к внутреннему CA
обеспечивает администратор. Замена схемы URL сама по себе не включает TLS.

Проверка сертификата HTTPS и запрет перенаправлений запросов с ключами
сохранены. Ошибки DNS, отказ соединения, таймаут и ошибки TLS теперь имеют
отдельные безопасные сообщения без ключей и содержимого ответов.
Проверка привязки локального listener остаётся отдельной.

Обновление установленного Core: `stolas update`. Повторно запустите
`stolas integrate n8n`, чтобы применить адрес в интеграции. Если workflow
уже существует, мастер подготовит файл для ручного обновления; после импорта
выполните Manual test в n8n.
