# Stolas v0.6.6

Релиз исправлений и упрощения обслуживания Stolas. Ядро измерений, SQLite и HTTP API остаются автономными; интеграция с n8n по-прежнему необязательна.

## Изменения

- **Docker:** обновлены закреплённые Alpine APK для `x86_64` и `aarch64`. Добавлена проверка доступности и SHA-256 зависимостей перед сборкой. Релизные зависимости не заменяются автоматически при ошибке загрузки.
- **Процессы:** Docker healthcheck использует exec-форму вместо shell, устраняя воспроизведённое накопление zombie-процессов при таймаутах. Проверены завершение по SIGTERM и сохранность данных.
- **CLI и установка:** унифицированы и сокращены диалоги установщика и настройки. Обновление текущей установки, сохранение конфигурации и SQLite, точки восстановления и откат проверены интеграционными тестами.
- **n8n:** сокращено число вопросов о подключении; проекты выбираются отдельно от credentials. Проверяется принадлежность credentials выбранному проекту, workflow создаётся неактивным. Для HTTP используется одно явное предупреждение о передаче ключей без шифрования.
- **Тесты:** устранены дублирующие и устаревшие сценарии; сохранены основные регрессии измерений, безопасности, API, хранения, обновления, Docker и n8n.

## Известные ограничения

На n8n Community 2.42.6 публичный API списка проектов возвращает HTTP 403 из-за лицензионного ограничения `PROJECT_ROLE_ADMIN`. Stolas не обходит авторизацию: вместо автоматического создания workflow предлагает ручной импорт, не меняя настройки Core. Работа автоматического выбора проектов с лицензированной n8n проверена контрактными тестами, но не подтверждена на реальном лицензированном экземпляре.

До первого стабильного публичного релиза не гарантируется обновление с исторических Stolas 0.4.0 и 0.5.0. Долговременная доступность закреплённых APK у Alpine CDN не гарантируется; отсутствующие пакеты требуют обновления закреплённых версий и повторной проверки.

## Обновление

Для установленного Stolas: `stolas update`. После обновления проверьте `stolas version`, `stolas diagnose` и историю результатов. Отдельный тест скорости выполняется вручную через `stolas run`; установка и обновление его автоматически не запускают.

Если используется n8n, при необходимости повторно выполните `stolas integrate n8n`. Для существующего workflow может потребоваться ручной импорт и проверка настроек в n8n.

Релиз рекомендуется сначала проверять на управляемом экземпляре с возможностью отката и сохранёнными SQLite, конфигурацией и точками восстановления.
