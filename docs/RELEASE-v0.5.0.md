# Stolas v0.5.0

## Изменения

- WAN: разные внешние IP с хотя бы одним разрешённым адресом дают предупреждение
  и позволяют измерение. Проверка помечается `mixed`, `verified=false`;
  внешний маршрут iperf3 не объявляется подтверждённым. Неподходящий заданный
  маршрут, отсутствие разрешённых IP и недоступная проверка блокируют тест.
- Проект и контейнер называются `stolas`, образ — `stolas:0.5.0`.
  При конфликте выбирается имя экземпляра. Теги `latest` не используются.
- Переход с v0.4.0 совместно меняет имена и структуру установки. Токен,
  API endpoint, конфигурация и фактически подключённый SQLite volume сохраняются.
  Ошибка после переключения сервиса возвращает предыдущую версию.
- Рабочий каталог содержит настройки, Compose, команду `stolas` и `.stolas/`.
  Тесты, CI и документация разработчика остаются в репозитории.
- `./stolas` объединяет измерение, историю, логи, настройку, обновление,
  откат, диагностику, интеграцию и удаление.
- `./stolas uninstall` сохраняет историю по умолчанию. `--purge` требует
  подтверждения и удаляет только собственные ресурсы и управляемые файлы.
  Общие образы, занятые чужими контейнерами volumes и посторонние файлы защищены.
- Неизвестный n8n Header Auth требует выбора даже при единственном варианте.
  Созданный Stolas credential переиспользуется по сохранённому ID.
  Ввод API key допускает видимую вставку; ключ не сохраняется.

## Проверки

- 185 сценариев Linux suite: 180 прошли, 5 явно пропущены; отдельные Docker/iperf3
  проверки выполняются следующими этапами CI.
- Реальный Docker: установка с локальным iperf3; замороженная v0.4.0 с записью
  SQLite; сбой после переключения и откат; обновление и повторное обновление;
  проверка истории через CLI/API; обычное удаление и purge. Соседний контейнер
  остаётся работающим.
- Production image: 68 проверок прошли, включая настоящий iperf3 loopback;
  117 сценариев установщика и opt-in пропущены внутри образа.
- Настоящий n8n 2.42.6 API, импорт трёх workflow, JavaScript, Alloy validate,
  две Docker-сети, Bearer-auth API, Compose и shell syntax.
- Настоящие Linux PTY: установка, навигация, ошибки, удаление и диагностика;
  цветной режим, NO_COLOR и ширина 80 символов.

## Ограничения

Azazel не затрагивался. Реальный WAN/PBR/LTE, удалённый n8n, Telegram,
установка пакетов на чистом apt-хосте и выполнение arm64 требуют проверки
в среде развёртывания. HTTPS-проверка за LAN-маршрутизатором не доказывает
внешний маршрут iperf3; для строгого запрета LTE настройте маршрутизацию серверов.

Команды установки, обновления с v0.4.0 и удаления — в [README](../README.md).
