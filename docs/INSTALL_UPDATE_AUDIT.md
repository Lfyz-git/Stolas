# Аудит установки и обновления (Issue #24)

Установка (`install`), обновление (`update`) и измерение — независимые операции.
Из мастера удалён автоматический CLI-замер, включая продолжение установки после
ошибки. Старый `--skip-first-test` принимается для совместимости без эффекта.
Старые отметки измерений в progress не инициируют новых запусков.

| Проверенный путь | Результат ревизии |
| --- | --- |
| `bootstrap.sh` → `install.sh` → `tools/deploy.py` | Загрузка исходников/пакетов, затем мастер; измерений нет |
| Мастер `tools/install.py`, новая установка | Только конфигурация, сборка и локальная готовность; автоматический замер удалён |
| `stolas update`, `--reuse-config` | Конфигурация и история сохранены; измерений нет; итог успеха сообщает deploy после фиксации транзакции |
| Перенастройка, `--configure-only` | Перенастройка проверяет сервис; configure-only только сохраняет настройки |
| Продолжение/`--recover`, старый checkpoint `measured` | Измерений нет независимо от прежнего результата |
| Ошибка обновления, rollback, `resources.restart` | Восстановление файлов/ресурсов и Compose up; замер не вызывается |
| Docker ENTRYPOINT/CMD, Compose restart, HEALTHCHECK | `agent serve`; `/healthz` не вызывает Runner; startup hooks и скрытого планировщика нет |
| Установка Docker/APK и сборка образа | Проверки версий утилит (`iperf3 --version`), без активной нагрузки |
| Подключение n8n (`tools/integrate.py`) | Проверяется `/healthz`, workflow создаётся неактивным; измерение при подключении не запускается |
| `stolas run`, `stolas run --json`, `agent run`, POST `/v1/tests` | Отдельные явные точки запуска измерения сохранены |
| Внешнее расписание n8n, отдельный `agent schedule` | Не изменены; установка не запускает schedule и не создаёт дополнительное задание |

Сохранены обязательные технические проверки: валидация конфигурации Python и
Compose, доступность Docker и принадлежность ресурсов, доступность локального
порта, контейнерный `validate`, ожидание готовности контейнера, авторизованный
GET `/healthz`. При подключении n8n также проверяются его API/авторизация и
доступность `/healthz` из выбранного окружения. Это проверки развёртывания,
не WAN-пробы; они не обращаются к POST `/v1/tests` и не вызывают Runner.run.
Загрузка исходников/зависимостей требует сети, но не измеряет интернет-канал.

SQLite volume, независимые расписания, конфигурация и транзакционные точки
восстановления не изменены. `serve` не запускает ни измерение, ни планировщик;
ранее отдельно настроенный клиент может продолжать выполнять своё расписание.

Регрессионные проверки: `tests/test_installer.py` (установка, обновление,
перенастройка, восстановление, старые checkpoints и ошибки локальных проверок),
`tests/test_install_separation.py` (старт/повторный старт serve, health/auth,
явный CLI/agent run), существующие тесты транзакций и CLI JSON.
`tests/test_runtime_docker.py` проверяет пустую историю после установки и
восстановления, затем явный `stolas run --json`, доступность результата через
API и сохранение истории при перенастройке во время cooldown/блокировки.
Проверка повторного старта serve в unit-тесте использует mock API-сервера.

При ревизии PR #25 прошли 63 теста установщика, разделения операций,
runtime-транзакций, отчёта обновления и представления busy; 3 Docker-теста
пропущены. Shell-тест установщика исключён из этого прогона: в полном прогоне
он не проходит проверку порта из-за запрета локальных сокетов в среде.
Полный набор также ограничен этим запретом; реальный Docker не запускался
из-за отсутствия доступа к Docker socket. Интеграционные проверки остаются
за отдельным запуском CI с доступом к локальным сокетам и Docker.
