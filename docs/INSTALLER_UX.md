# UX-аудит установщика Stolas v0.3.0

Проверен весь путь: bootstrap.sh → install.sh → tools/deploy.py → tools/install.py, включая повторную установку, восстановление, настройки n8n и применение Compose. Измерительный агент не изменён.

Принцип: **Discover → Validate → Propose → Confirm → Apply → Verify**.

## Обнаруженные проблемы и решения

| Проблема v0.2.0 | Решение v0.3.0 |
| --- | --- |
| Пользователь ищет Docker gateway и вводит IP | чтение Docker API и интерфейсов Linux; один проверенный вариант выбирается автоматически |
| URL ещё не установленного Stolas вводится вручную | вычисляется из адреса, порта и топологии; показывается в сводке |
| Любой gateway можно принять за адрес хоста | сверка с host IPv4 и IPAM; macvlan/ipvlan не принимаются за обычный bridge |
| По названию контейнера трудно найти n8n | официальный образ, Compose metadata, имена; worker/webhook/runner исключаются; слабые совпадения требуют выбора |
| Много технических вопросов с безопасными defaults | обычный путь короткий; расширенные параметры доступны из сводки |
| Повторный опрос сохранённых значений | существующая установка открывает сводку; исправляется выбранный раздел |
| Все ошибки ввода одинаковые | сообщения о формате, диапазоне, отсутствующем интерфейсе, правах, конфликте IPAM, занятом порте |
| Нет предварительного просмотра применения | сводка с секретами, скрытыми от вывода; отдельное apply |
| Прерывание теряет данные, update принимает исходники за завершённую установку | приватный черновик, checkpoints; наличие исходников отделено от наличия .env/config |
| После успешного CLI и ошибки n8n повторяется нагрузочный тест | measured checkpoint позволяет продолжить импорт без повторного теста |
| Запрос с хоста принимается за связь из n8n | authenticated fetch из выбранного контейнера; при ошибке нет fallback на проверку хоста |
| Частичный импорт n8n может дублировать ресурсы | сохранённые ID переиспользуются, неоднозначный pending запрос не повторяется |
| Диагностика требует запуска мастера | --diagnose без TTY, записи целевого каталога, установки пакетов или Docker mutations |

## Все вопросы: классификация и судьба

A — обнаруживаемый факт. B — безопасное значение по умолчанию. C — намерение/выбор пользователя. D — секрет или сведения, которым нельзя доверять без пользователя.

| Вопрос / параметр | Категория | Поведение |
| --- | --- | --- |
| Каталог установки | C | --dir или один запрос с HOME/stolas по умолчанию; права/пустота/symlink проверяются |
| Наличие Python, apt, curl/wget, tar | A | обнаружение оболочкой/диагностикой; отдельное согласие C нужно лишь для установки отсутствующего Python |
| Наличие Docker, доступ к API/socket | A | info/context, ограниченное по времени чтение; sudo -n не запрашивает пароль |
| Версия, архитектура Engine, Compose | A | обнаружение; существующий Engine не заменяется |
| Установить отсутствующий Docker | C | явно указан в сводке применения; отдельного дублирующего вопроса после apply нет |
| Существующая установка, версия, этап | A | файлы состояния, manifest, наличие конфигурации, checkpoints; неизвестная версия так и обозначается |
| Повторная настройка / update / rollback / cancel | C | выбор действия или --action |
| Имя узла | A/B | hostname для новой установки, сохранённое имя для существующей; можно изменить в measurements |
| seconds, parallel | B | 10 секунд, 4 потока; расширенная настройка |
| connect_timeout, process_timeout, cycle_timeout | B | проверенные defaults/сохранённые значения; расширенная настройка |
| attempts_per_server, busy_attempts_per_server, retry_delay | B | ограниченные budgets; расширенная настройка |
| reserve_every, min_interval, history_limit | B | defaults/сохранённые значения; расширенная настройка |
| bind_address | C/D | автоматически не выбирается: намеренное ограничение исходящего iperf трафика; расширенная настройка |
| WAN required / off | C | осознанный выбор; off не включается ради успешной установки |
| expected_public_cidrs | D | обязательный ввод для required, если неизвестно; текущий IP не угадывается как основной WAN |
| public_ip_urls | B/C | независимые HTTPS defaults; изменить в measurements |
| verification_timeout, source_timeout, min_confirmations | B | безопасные budgets/сохранённые значения; расширенная настройка |
| Ожидаемые route.interface/gateway | C/D | пользовательская политика основного WAN, а не догадка по текущему маршруту; расширенная настройка |
| Группы primary/additional/emergency, состав и число серверов | B/C | defaults/сохранённые списки; можно изменить без ограничения числа серверов |
| selection random/sequential каждой группы | C | сохранённое/default sequential; расширенная настройка |
| ID/host/ports серверов, пороги DL/UL | B/C/D | исходные defaults; пользовательские endpoints/пороги задаются явно в расширенном разделе |
| STOLAS_LISTEN | A | вычисляется по подтверждённой топологии; 0.0.0.0 не выбирается |
| STOLAS_PORT, его занятость | B/A | 8080/сохранённый порт; bind-проверка, при чужой занятости — следующий свободный порт со сводкой |
| API token | B/D | случайный или сохранённый без вопроса; ручной секрет меняется только в разделе api |
| later/export/api/keep | C | понятные описания способов интеграции |
| Локальный Docker / ОС / LAN / VPN / proxy | C | намерение пользователя; обнаруженные варианты предлагаются по умолчанию |
| Имя/ID единственного подтверждённого n8n | A | автоматически; несколько экземпляров — выбор C по имени/образу/Compose проекту |
| Сетевой режим, IPAM, gateway, host interface | A | обнаружение и сверка; несколько пригодных сетей — именованный выбор C |
| IPv4 хоста в Docker-сети | A | ручной вопрос удалён |
| Endpoint Stolas в Docker/ОС/VPN | A | вычисляется автоматически; ручной вопрос удалён |
| Доверенный VPN-интерфейс | C | выбор обнаруженного интерфейса; наличие IP не доказывает доверие сети |
| Внешний HTTPS endpoint reverse proxy | D | ввод существующего DNS/TLS маршрута; его нельзя надёжно получить из Docker metadata |
| Telegram chat id | D | явный ввод; известное значение сохраняется |
| Интервал, timezone | B/A/C | 3 часа; подтверждённый timezone хоста или Etc/UTC; изменения в schedule |
| Политика Telegram, час daily summary | C/B | явный выбор политики; час по умолчанию 9 |
| URL существующего n8n API | D | ввод реального адреса; метаданные Docker не доказывают внешний TLS/path маршрута |
| n8n API key, Telegram bot token | D | скрытый ввод, checkpoint 0600; при продолжении известный секрет не спрашивается снова |
| Продолжить черновик / сохранённую конфигурацию | C | выбор при обнаружении черновика |
| apply / исправление раздела / cancel | C | последняя сводка до сохранения рабочей конфигурации и развёртывания |

## Обычный сценарий на Azazel

1. Пользователь запускает закреплённый bootstrap v0.3.0 с --dir /opt/stolas.
2. Мастер обнаруживает существующий Docker, n8n и его сеть. Если найдены один n8n и один допустимый bridge gateway 172.18.0.1 на интерфейсе Linux, выбирает их автоматически.
3. Пользователь задаёт основной WAN IPv4/CIDR (либо осознанный off), выбирает export/api, принимает предложенный локальный Docker, вводит chat id и политику Telegram.
4. Сводка показывает STOLAS_LISTEN=172.18.0.1, свободный порт и автоматически вычисленный http://172.18.0.1:8080. Пользователь выбирает apply либо исправляет отдельный раздел.
5. Мастер сохраняет рабочие настройки, запускает только Stolas, проверяет Bearer HTTP из n8n, выполняет один CLI-цикл и готовит неактивный workflow.
6. Пользователь проверяет Telegram и активирует расписание в n8n.

Если исходники v0.2.0 уже распакованы, но настройка прервана до записи .env/config, update v0.3.0 распознаёт незавершённую установку и запускает новый мастер. Секреты, которые старая версия никогда не записала, восстановить невозможно.

## Границы автоматизации

Наличие IP не доказывает работоспособность сети; после применения требуется запрос из n8n. Macvlan, remote Docker, отсутствующий host IPv4, нехватка прав и нестандартная сеть дают явную причину без догадки по диапазону 172.x. Отдельные настройки firewall/VPN/TLS требуют администрирования и не изменяются мастером.

До подтверждения разрешены чтение системы, проверка bind без listen, загрузка собственных исходников и запись приватного черновика. Нет Docker build/up, вызовов API создания ресурсов или изменения действующей конфигурации. При отмене загруженные исходники восстанавливаются из backup, рабочие файлы/контейнеры не меняются.

Диагностика не запрашивает публичный IP автоматически: разовое наблюдение не идентифицирует основной WAN и не оправдывает разрешение LTE. Существующая защита required, ограничения iperf и минимальные привилегии агента сохранены.
