# Stolas

Stolas измеряет скорость IPv4 TCP через iperf3, хранит результаты в SQLite
и предоставляет CLI и HTTP API. n8n, Telegram и сервер логов необязательны.

## Установить

В SSH-терминале Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/Lfyz-git/Stolas/v0.5.0/bootstrap.sh | sh -s -- --dir /opt/stolas
```

Каталог должен принадлежать вам. Нужны Python 3.10+, `curl` или GNU `wget`,
`tar`, `sha256sum` и локальный Docker с Compose. На системах с apt мастер
предложит установить отсутствующие Python и Docker. Поддерживаются amd64 и arm64;
сборка и выполнение в CI проверяются на amd64.

Мастер спросит способ проверки основного канала и разрешённый внешний IPv4/CIDR,
покажет сводку, создаст токен API и выполнит один тест скорости.
Из сводки можно изменить серверы, пороги и доступ к API.
По умолчанию API слушает `127.0.0.1:8080`.

Обычные имена: проект и контейнер `stolas`, образ `stolas:0.5.0`.
При конфликте мастер предложит выбрать имя экземпляра.
В рабочем каталоге остаются `compose.yaml`, `.env`, `stolas`, `config/local.json`
и служебный каталог `.stolas/`. Исходники сборки, состояние и резервные копии
сгруппированы внутри него; тесты и документация разработчика не устанавливаются.

[Установка и восстановление](docs/INSTALLATION.md) · [Диалог мастера](docs/INSTALLER_UX.md)

## Запустить измерение

Из каталога установки:

```sh
./stolas run
```

Команда показывает результат и предупреждения. Для обработки скриптом:

```sh
./stolas run --json
```

stdout содержит один JSON-объект, события идут в stderr.
`status: "ok"` означает успешное измерение. Параллельные и слишком частые
запуски отклоняются. Расписание задаёт внешний клиент; установщик выполняет
только первичный тест.

## Получить результаты

```sh
./stolas history
```

История возвращается в JSON. HTTP API принимает Bearer-токен из `.env`:

```sh
set -a
. ./.env
set +a
curl -fsS -H "Authorization: Bearer $STOLAS_API_TOKEN" \
  "http://$STOLAS_LISTEN:$STOLAS_PORT/v1/results/latest"
```

[Эндпоинты, статусы и CLI](docs/API.md). API доступен любому HTTP-клиенту.

## Посмотреть логи

```sh
./stolas logs
```

По умолчанию — JSON Lines, уровень INFO. Формат и уровень задаются в `.env`;
после изменения выполните `docker compose up -d stolas`.
[События и подключение существующего сборщика логов](docs/LOGGING.md).

## Изменить настройки

```sh
./stolas configure
```

Мастер открывает сохранённую сводку. Измерения задаются в `config/local.json`,
параметры сервиса — в `.env`. Не публикуйте токены, состояние и резервные копии.

Серверы разделены на основные, дополнительные и аварийные. В каждой группе
разрешено любое число серверов; выбор — по очереди или случайно.
[Все параметры](docs/CONFIGURATION.md).

Проверка WAN сверяет ответы HTTPS-сервисов с разрешёнными адресами.
Разные IP при наличии разрешённого адреса дают предупреждение и позволяют
измерение; результат проверки остаётся неопределённым. Если разрешённого
подтверждения нет, измерение блокируется. Локальный шлюз не доказывает,
какой внешний канал маршрутизатор выберет для iperf3.
При строгом запрете измерений через LTE настройте маршрут к измерительным
серверам на своём маршрутизаторе. [Логика WAN и её границы](docs/CONFIGURATION.md#проверка-канала).

## Обновить

В установленной v0.5.0:

```sh
./stolas update
```

Для перехода с v0.4.0:

```sh
curl -fsSL https://raw.githubusercontent.com/Lfyz-git/Stolas/v0.5.0/bootstrap.sh | sh -s -- --dir /opt/stolas --action update
```

Обновление переносит структуру и имена совместно, сохраняет токен, конфигурацию
и **тот же SQLite volume**. Повторный нагрузочный тест не выполняется.
При ошибке восстанавливаются прежние файлы и сервис.
`./stolas rollback` возвращает предыдущую установленную версию.

## Удалить

```sh
./stolas uninstall
```

По умолчанию сохраняются история, настройки и команда управления.
Для полного удаления:

```sh
./stolas uninstall --purge
```

Команда покажет каталог и volume и потребует ввести `УДАЛИТЬ`.
Удаление работает без GitHub; посторонние файлы и чужие Docker-ресурсы сохраняются.
[Подробности удаления](docs/INSTALLATION.md#удалить).

## Подключить n8n

```sh
./stolas integrate n8n
```

Мастер подготовит файл для ручного импорта либо подключит неактивный workflow
через API. Telegram использует существующие credentials в n8n.
Неизвестный Header Auth всегда требует явного выбора.
[Инструкция n8n](docs/N8N.md).

`./stolas help` — команды; `./stolas diagnose` — диагностика.
