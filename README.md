# Stolas

Stolas — самостоятельный агент измерения скорости IPv4 TCP через iperf3.
Он проверяет интернет-канал, сохраняет историю в SQLite и отдаёт JSON через CLI и HTTP API.

## Установить

В SSH-терминале Linux-хоста выполните:

```sh
curl -fsSL https://raw.githubusercontent.com/Lfyz-git/Stolas/v0.4.0/bootstrap.sh | sh
```

Нужны Python 3.10+, `curl` или GNU `wget`, `tar`, `sha256sum` и доступ к локальному Docker.
Отсутствующие Python и Docker мастер предложит установить на системе с apt.
Существующий Docker сохраняется. Поддерживаются Linux amd64 и arm64.

Мастер спросит каталог, способ проверки основного интернет-канала и его разрешённый
внешний IP/CIDR. Затем покажет сводку и запросит подтверждение. Токен API создаётся
автоматически. После запуска выполняется один тест скорости.

n8n, Telegram и сервер логов для установки и работы **не нужны**.

По умолчанию API слушает `127.0.0.1:8080`. Из сводки можно изменить параметры
измерений, серверы и доступ к API. [Полный диалог и цветной интерфейс](docs/INSTALLER_UX.md).

Для `/opt/stolas` передайте `--dir /opt/stolas`. Каталог должен принадлежать вам:
пустой существующий каталог подходит. Не удаляйте его после прерывания установки —
повторный запуск предложит продолжить. [Установка, обновление и восстановление](docs/INSTALLATION.md).

## Запустить тест

Команды ниже выполняются из каталога установки:

```sh
cd /opt/stolas
docker compose exec -T stolas python3 -m agent run
```

Результат — один JSON-объект. `status: "ok"` означает успешное измерение.
Логи идут отдельно в stderr. Измерение ограничено по времени; параллельный запуск
и слишком частые запросы отклоняются.

Stolas перебирает основные серверы; дополнительные подтверждают низкую скорость
или заменяют недоступные, аварийные используются последними. В каждой группе
может быть любое число серверов, с выбором по очереди или в случайном порядке.

## Получить результаты

```sh
docker compose exec -T stolas python3 -m agent history
```

HTTP API принимает Bearer-токен из `.env`:

```sh
set -a
. ./.env
set +a
curl -fsS -H "Authorization: Bearer $STOLAS_API_TOKEN" \
  "http://$STOLAS_LISTEN:$STOLAS_PORT/v1/results/latest"
```

Все эндпоинты, статусы и примеры — в [описании API](docs/API.md).
API доступен любому клиенту: собственному скрипту, Home Assistant, Zabbix, n8n и другим.
Для графиков потребитель читает результаты и передаёт их в выбранное хранилище.

## Изменить настройки

```sh
sh install.sh --action reconfigure
```

Сохранённая установка сразу открывает сводку. Измените нужный раздел и подтвердите.
Конфигурация измерений — `config/local.json`, токен и параметры сервиса — `.env`.
Файлы `.env`, черновики и резервные копии не публикуйте.

Режим проверки основного канала по умолчанию запрещает тест, если внешний IP
не входит в разрешённые CIDR или его нельзя проверить. Текущий внешний адрес
не считается доказательством основного WAN: он может принадлежать LTE/VPN.
При динамическом IP обновите разрешённый адрес или используйте известный диапазон провайдера.
Проверка IP не заменяет ограничения маршрутизации на вашем маршрутизаторе.

[Параметры измерений, WAN и групп серверов](docs/CONFIGURATION.md).
Расписание задаёт внешний клиент; установка запускает только один первичный тест.

## Посмотреть логи

```sh
docker compose logs --tail 50 -f stolas
```

По умолчанию — JSON Lines, уровень INFO. Добавьте в `.env`, например,
`STOLAS_LOG_LEVEL=DEBUG` или `STOLAS_LOG_FORMAT=text`, затем примените:

```sh
docker compose up -d stolas
```

История результатов остаётся в SQLite; логи её не заменяют.
[События, journalctl и пример Alloy → Loki](docs/LOGGING.md).

## Подключить интеграцию

После установки можно запустить отдельный мастер:

```sh
python3 tools/integrate.py n8n
```

Он подготовит неактивный workflow для ручного импорта либо подключит его через API n8n.
Ручной импорт не требует API key. Telegram Bot Token остаётся в n8n;
мастер использует существующие credentials и не создаёт Telegram credential.
Ошибка интеграции не останавливает Core. [Инструкция для n8n](docs/N8N.md).
